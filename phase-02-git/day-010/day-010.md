# Day 10/100 — Remote & Collaboration

> **Goal:** By the end of this session, you'll understand how Git works with remote repositories — push, pull, fetch, clone, and how teams collaborate through Pull Requests. You'll create a real PR on GitHub.

## Part 1: Why This Matters for Your Projects (10 min)

You've been working with Git locally — commits, branches, merges. But your code only lives on your laptop. If your laptop dies, everything dies.

Remote repositories solve this. GitHub is where your code lives online. Every push saves it to the cloud. Every pull brings the latest version to your machine.

But here's the real value: Pull Requests. That's how teams review code before it goes to production. You push to a branch, open a PR, someone reviews it, and you merge. This is the backbone of every professional DevOps workflow.

| Command | What it does | When I'd use it |
|---------|--------------|-----------------|
| `git remote add origin <url>` | Connect local repo to GitHub | First time setting up a repo |
| `git push origin main` | Upload local commits to GitHub | After committing locally |
| `git pull origin main` | Download latest changes from GitHub | Before starting work each day |
| `git fetch origin` | See what changed without downloading | Check for updates before pulling |
| `git clone <url>` | Download a repo from GitHub | Start working on a new project |

## Part 2: Connecting to GitHub (15 min)

### The Problem

You have a local Git repo on your laptop — say `Online-voting-system`. You've made 5 commits locally. But GitHub doesn't know about any of them. Your code is stuck on your machine.

### The Command

First, check if you already have a remote connected:

```bash
cd ~/devops_learning/projects/Online-voting-system
git remote -v
```

If you see nothing, you need to add one:

```bash
git remote add origin https://github.com/prathameshlonare/Online-voting-system.git
```

Let's break it down:
- `git remote add` = connect a remote repository
- `origin` = the name (convention is "origin" for your main remote)
- The URL = your repo's address on GitHub

### Try It Now

```bash
cd ~/devops_learning/projects/Online-voting-system
git remote -v
```

You'll see output like:

```
origin  https://github.com/prathameshlonare/Online-voting-system.git (fetch)
origin  https://github.com/prathameshlonare/Online-voting-system.git (push)
```

Two lines — one for fetch (downloading), one for push (uploading). Same URL, different directions.

## Part 3: Pushing to GitHub (15 min)

### The Problem

You have 3 commits locally on `main`. You want them on GitHub so they're backed up and others can see them.

### The Command

```bash
git push origin main
```

Let's break it down:
- `git push` = upload commits
- `origin` = which remote (the one we just set up)
- `main` = which branch to push

First time pushing a new branch? You need to set the upstream:

```bash
git push -u origin main
```

The `-u` flag sets "upstream tracking" — after this, future pushes just need `git push` without specifying origin and branch.

### Try It Now

```bash
cd ~/devops_learning/projects/Online-voting-system
git push -u origin main
```

You'll see output like:

```
Enumerating objects: 15, done.
Counting objects: 100% (15/15), done.
Delta compression using up to 8 threads
Compressing objects: 100% (12/12), done.
Writing objects: 100% (15/15), 1.23 KiB | 1.23 MiB/s, done.
Total 15 (delta 3), reused 0 (delta 0)
remote: Resolving deltas: 100% (3/3), done.
To https://github.com/prathameshlonare/Online-voting-system.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

The key line: `[new branch] main -> main` — your branch is now on GitHub.

### What Just Happened

| Step | What Git Did |
|------|-------------|
| Pack objects | Compressed your commits into files |
| Upload | Sent them to GitHub's servers |
| Create branch | Made a `main` branch on GitHub |
| Track | Linked your local `main` to `origin/main` |

## Part 4: Pull and Fetch (15 min)

### The Problem

You pushed your code yesterday. Today, you've made changes on another machine — or a teammate pushed something. Your local copy is behind. You need to pull the latest changes.

### The Command: Pull

```bash
git pull origin main
```

This downloads and merges changes from GitHub into your local branch. It's `git fetch` + `git merge` in one step.

### The Command: Fetch

```bash
git fetch origin
```

This checks what changed on GitHub but does NOT merge. It's safer — you can review before combining.

### Try It Now

```bash
cd ~/devops_learning/projects/Online-voting-system
git fetch origin
```

Output:

```
remote: Enumerating objects: 5, done.
remote: Counting objects: 100% (5/5), done.
remote: Total 3 (delta 2), reused 0 (delta 0)
Unpacking objects: 100% (3/3), done.
From https://github.com/prathameshlonare/Online-voting-system
   a1b2c3d..e4f5g6h  main     -> origin/main
```

The line `a1b2c3d..e4f5g6h` shows what changed. You can see the difference before pulling:

```bash
git log main..origin/main --oneline
```

This shows commits on GitHub that you don't have locally.

### When to Use Which

| Situation | Use |
|-----------|-----|
| Daily routine, starting work | `git pull origin main` |
| Suspicious, want to review first | `git fetch origin` then check |
| Multiple people editing same files | Always fetch first, then merge carefully |

## Part 5: Clone — Starting Fresh (10 min)

### The Problem

You're on a new machine, or you deleted a folder, or you want a fresh copy. Cloning downloads an entire repo from GitHub.

### The Command

```bash
git clone https://github.com/prathameshlonare/Online-voting-system.git
```

This creates a folder called `Online-voting-system` with all files, all history, and remote tracking already set up.

### Try It Now

```bash
cd ~/devops_learning
git clone https://github.com/prathameshlonare/Dorm-and-Dish.git dorm-and-dish-test
ls dorm-and-dish-test
```

You'll see all files — ready to go. No `git init`, no `git remote add` — clone handles everything.

## Part 6: Build Task — Create a Pull Request (30 min)

Now let's do the real thing. You'll create a PR on one of your repos. This is how every code change goes through in a professional team.

### What We're Doing

Adding a `.gitignore` file to `Online-voting-system` — a file that tells Git which files to ignore.

### Step 1: Create a Branch

```bash
cd ~/devops_learning/projects/Online-voting-system
git checkout main
git pull origin main
git checkout -b feature/add-gitignore
```

### Step 2: Create the .gitignore File

```bash
cat > .gitignore << 'EOF'
# Dependencies
node_modules/
.env

# Build output
build/
dist/

# OS files
.DS_Store
Thumbs.db

# IDE
.vscode/
.idea/

# Logs
*.log
npm-debug.log*
EOF
```

### Step 3: Commit and Push

```bash
git add .gitignore
git commit -m "Add .gitignore for Node.js project"
git push -u origin feature/add-gitignore
```

### Step 4: Create the PR on GitHub

1. Go to `github.com/prathameshlonare/Online-voting-system`
2. You'll see a yellow banner: "feature/add-gitignore had recent pushes — Compare & pull request"
3. Click that button
4. Title: "Add .gitignore for Node.js project"
5. Description: "Adds .gitignore to exclude node_modules, build files, and IDE configs."
6. Click "Create pull request"

### Step 5: Merge It

1. On the PR page, scroll down
2. Click "Merge pull request"
3. Click "Confirm merge"
4. Click "Delete branch" (cleanup)

### Step 6: Back to Local

```bash
git checkout main
git pull origin main
git branch -d feature/add-gitignore
```

### What You Just Built

You created a real Pull Request — the same workflow used at Amazon, Google, every professional team. The flow is:

1. Branch → 2. Commit → 3. Push → 4. Open PR → 5. Review → 6. Merge → 7. Cleanup

This is the backbone of CI/CD and DevOps collaboration.
