## Part 3: Project Structure for GitHub (15 min)

### The Problem

Your scripts work locally. But if you push them to GitHub as-is, no one will understand what they do. You need:
- Clear folder structure
- Professional README
- Script documentation

### The Standard Structure

GitHub projects follow this pattern:

```
project-name/
├── README.md           # What is this? How do I use it?
├── scripts/            # Your code
│   ├── category1/
│   └── category2/
├── docs/               # Documentation
└── LICENSE             # (optional)
```

## Part 5: Pushing to GitHub (20 min)

### The Problem

Your project is ready locally. Now you need to get it on GitHub so recruiters can see it.

### Step 1: Create a GitHub Repo

1. Go to github.com
2. Click the **+** icon → **New repository**
3. Name: `sysadmin-toolkit`
4. Description: "Linux system administration toolkit — bash scripts for permissions, processes, networking, and services"
5. Make it **Public** (recruiters need to see it)
6. Don't initialize with README (you already have one)
7. Click **Create repository**

### Step 2: Initialize Git and Push

```bash
cd devops-journey/sysadmin-toolkit

# Initialize git
git init

# Add all files
git add .

# Commit
git commit -m "feat: sysadmin-toolkit - Linux scripts for permissions, processes, networking, services"

# Add remote (replace YOUR-USERNAME with your GitHub username)
git remote add origin https://github.com/YOUR-USERNAME/sysadmin-toolkit.git

# Push
git branch -M main
git push -u origin main
```

### Step 3: Verify

1. Go to your GitHub repo: `github.com/YOUR-USERNAME/sysadmin-toolkit`
2. You should see all your files
3. The README.md should display automatically
