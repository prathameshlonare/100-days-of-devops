### Anatomy of a Workflow

```yaml
name: CI Pipeline                    # 1. Name (shows in GitHub UI)

on:                                 # 2. Trigger
  push:
    branches: [main]                # Run on push to main
  pull_request:
    branches: [main]                # Run on PR to main

jobs:                               # 3. Jobs
  lint-and-test:                    # Job name (your choice)
    runs-on: ubuntu-latest          # 4. Runner (what server)
    steps:                          # 5. Steps
      - uses: actions/checkout@v4   # Step 1: Clone repo
      - uses: actions/setup-node@v4 # Step 2: Install Node
        with:
          node-version: '18'
      - run: npm ci                 # Step 3: Install deps
      - run: npm run lint           # Step 4: Lint
      - run: npm test               # Step 5: Test
```

### Line-by-Line Breakdown

| Line | What it does | Why it matters |
|------|--------------|----------------|
| `name: CI Pipeline` | Labels the workflow | Shows in GitHub Actions tab |
| `on: push: branches: [main]` | Triggers on push to main | Every commit to main runs tests |
| `on: pull_request: branches: [main]` | Triggers on PR to main | Tests run before merge |
| `jobs:` | Starts the jobs section | You can have multiple jobs |
| `lint-and-test:` | Names this job | You can reference it later |
| `runs-on: ubuntu-latest` | Which server to use | GitHub provides free Linux runners |
| `steps:` | List of commands | Each step runs in order |
| `uses: actions/checkout@v4` | Clones your repo | Without this, no code to test |
| `uses: actions/setup-node@v4` | Installs Node.js | Your project needs Node 18 |
| `with: node-version: '18'` | Specifies Node version | Matches your local environment |
| `run: npm ci` | Installs dependencies | Clean install (not npm install) |
| `run: npm run lint` | Runs linter | Catches style/syntax errors |
| `run: npm test` | Runs tests | Catches broken functionality |

## Part 3: Triggers — When Should the Pipeline Run? (15 min)

### The Problem

You want tests to run on every push to main. But what about pull requests? What about pushes to feature branches?

### Trigger Options

```yaml
on:
  push:
    branches: [main, develop]      # Run on push to main or develop
  pull_request:
    branches: [main]               # Run on PR targeting main
  schedule:
    - cron: '0 2 * * 1'           # Run every Monday at 2 AM UTC
  workflow_dispatch:                # Manual trigger (button in UI)
```

### Common Patterns

| Pattern | Use case | Example |
|---------|----------|---------|
| `push: branches: [main]` | Tests on every commit to main | Essential |
| `pull_request: branches: [main]` | Tests before merge | Essential |
| `schedule: cron: '...'` | Nightly builds | Optional |
| `workflow_dispatch` | Manual trigger | Debugging |

### Try It Now

```yaml
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
```

## Part 4: Jobs and Steps — The Assembly Line (20 min)

### The Problem

One job runs all steps in sequence. But what if you want lint and test to run at the same time? Or what if build should only run if tests pass?

### Multiple Jobs

```yaml
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '18'
      - run: npm ci
      - run: npm run lint

  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '18'
      - run: npm ci
      - run: npm test

  build:
    needs: [lint, test]            # Only runs if BOTH lint and test pass
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: docker build -t voting-frontend .
```

### Job Dependencies

```
┌───────┐     ┌───────┐
│ lint  │     │ test  │     ← Run in parallel
└───┬───┘     └───┬───┘
    │             │
    └──────┬──────┘
           │
           ▼
      ┌─────────┐
      │  build  │             ← Runs only if both pass
      └─────────┘
```

### Step Types

| Type | Syntax | What it does |
|------|--------|--------------|
| `uses:` | `uses: actions/checkout@v4` | Runs a pre-built action |
| `run:` | `run: npm test` | Runs a shell command |
| `with:` | `with: node-version: '18'` | Passes inputs to an action |
| `env:` | `env: NODE_ENV: test` | Sets environment variables |

## Part 5: Build Task — Real Workflow for Online-voting-system (30 min)

Now let's build the actual workflow you'll use.

### Create the File

```bash
cd ~/Online-voting-system
nano .github/workflows/ci.yml
```

### Write This Workflow

```yaml
name: CI Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

env:
  NODE_VERSION: '18'

jobs:
  lint:
    name: Lint
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run linter
        run: npm run lint

  test:
    name: Test
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test

      - name: Upload test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-results
          path: coverage/
```

### Make It Executable

```bash
git add .github/workflows/ci.yml
git commit -m "ci: add lint and test pipeline"
git push origin main
```

### Test It

Go to GitHub → Actions tab. You should see:
- Two jobs running in parallel: Lint and Test
- Green checkmarks when both pass
- Test coverage uploaded as artifact

### What You Just Built

A real CI pipeline that:
- Runs on every push to main
- Runs on every pull request to main
- Lints your code (catches style errors)
- Tests your code (catches bugs)
- Runs lint and test in parallel (faster)
- Caches npm dependencies (even faster)
- Uploads test coverage as artifact

## Part 6: Recap (5 min)

### What You Learned

| Concept | Use Case | Online-voting-system |
|---------|----------|---------------------|
| Workflow | Pipeline definition | `.github/workflows/ci.yml` |
| Job | Group of steps | lint, test |
| Step | One command | npm test |
| Trigger | When to run | push, pull_request |
| `uses:` | Pre-built action | actions/checkout@v4 |
| `run:` | Shell command | npm run lint |
| `needs:` | Job dependency | build needs lint + test |
| `env:` | Environment variables | NODE_VERSION: '18' |

### The Pattern

When creating a GitHub Actions workflow:
1. **Start with trigger** — when should it run?
2. **Add jobs** — what needs to happen?
3. **Add steps** — how does each job work?
4. **Add dependencies** — what depends on what?
5. **Test it** — push and watch
