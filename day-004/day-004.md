# Day 4/100 — File Permissions

> **Goal:** Understand Linux file permissions so you can secure servers, fix "Permission denied" errors, and set up web servers correctly. You'll build a permissions setup script.

---

## Part 1: Why Permissions Matter in DevOps (10 min)

You deploy a web app. It starts, but users get "403 Forbidden." Why?

The web server can't read the files. Wrong permissions.

Permissions are Linux's security model. They define:
- **Who** can access a file
- **What** they can do (read, write, execute)
- **How** it affects other files in the directory

Get permissions wrong → security holes OR broken services.

### What We'll Cover

| Command | What it does |
|---------|--------------|
| `chmod` | Change permissions |
| `chown` | Change owner |
| `chgrp` | Change group |
| `ls -l` | Read permissions |
| `stat` | Detailed file info |

## Part 2: Reading Permissions (20 min)

### The Problem

You run `ls -l` and see this:

```
-rwxr-xr-- 1 prathamesh prathamesh 4096 Jul 01 10:00 script.sh
```

What does `-rwxr-xr--` mean?

### Breaking It Down

```
- rwx r-x r--
│ │   │   │
│ │   │   └─ Others (everyone else)
│ │   └───── Group (your group)
│ └───────── Owner (you)
└──────────── Type (- = file, d = directory)
```

| Symbol | Meaning | Numeric |
|--------|---------|---------|
| `r` | Read | 4 |
| `w` | Write | 2 |
| `x` | Execute | 1 |
| `-` | No permission | 0 |

### The Numeric System

Add the numbers for each position:

| Permission | Numeric | Example |
|------------|---------|---------|
| rwx | 7 | 4+2+1 |
| rw- | 6 | 4+2+0 |
| r-x | 5 | 4+0+1 |
| r-- | 4 | 4+0+0 |
| --- | 0 | 0+0+0 |

So `-rwxr-xr--` = `754`

### Common Permissions

| Permission | Use Case |
|------------|----------|
| `755` | Scripts, executables (owner can write, others can run) |
| `644` | Regular files (owner can write, others can read) |
| `700` | Private directories (only owner can access) |
| `600` | Private keys, SSH keys |
| `1777` | `/tmp` (everyone can write, but can't delete others' files) |

### Try It

```bash
ls -la /etc/passwd
ls -la /etc/shadow
ls -la /tmp
ls -la ~/.ssh
```

Notice:
- `/etc/passwd` is `644` (everyone can read, only root can write)
- `/etc/shadow` is `640` (only root can read — contains passwords)
- `/tmp` has `drwxrwxrwt` — the `t` is the sticky bit (we'll cover that)

### Exercise 1

1. Run `ls -la ~` — what permissions do your files have?
2. Run `ls -la /etc/ssh/sshd_config` — SSH config permissions
3. Run `stat /etc/hostname` — detailed info including permissions

## Part 3: Changing Permissions with chmod (20 min)

### The Problem

You wrote a script. It doesn't run. You get "Permission denied."

```bash
./myscript.sh
bash: ./myscript.sh: Permission denied
```

### The Fix

```bash
chmod +x myscript.sh
```

Now it runs.

### chmod with Symbols

```bash
chmod +x file.sh       # Add execute
chmod -x file.sh       # Remove execute
chmod +w file.sh       # Add write
chmod u+x file.sh      # Add execute for owner only
chmod g+w file.sh      # Add write for group
chmod o+r file.sh      # Add read for others
chmod u=rwx,g=rx,o=r file.sh  # Set exactly
```

| Symbol | Meaning |
|--------|---------|
| `u` | User (owner) |
| `g` | Group |
| `o` | Others |
| `a` | All (u+g+o) |
| `+` | Add permission |
| `-` | Remove permission |
| `=` | Set exactly |

### chmod with Numbers

```bash
chmod 755 file.sh      # rwxr-xr-x
chmod 644 file.txt     # rw-r--r--
chmod 700 private/     # rwx------
chmod 600 key.pem      # rw-------
chmod 777 public.sh    # rwxrwxrwx (avoid this — everyone can do everything)
```

### Try It

```bash
# Create a test file
touch testfile.sh

# Check permissions
ls -la testfile.sh
# -rw-r--r-- (644)

# Make it executable
chmod +x testfile.sh
ls -la testfile.sh
# -rwxr-xr-x (755)

# Make it private
chmod 700 testfile.sh
ls -la testfile.sh
# -rwx------ (700)

# Clean up
rm testfile.sh
```

### Exercise 2

1. Create `testfile.txt` — what are its default permissions?
2. `chmod 644 testfile.txt` — what changes?
3. `chmod 755 testfile.txt` — now it's executable
4. `chmod 000 testfile.txt` — no one can access it
5. `chmod 644 testfile.txt` — back to normal

## Part 4: Changing Owner with chown (10 min)

### The Problem

You downloaded a file as your user, but the web server (running as `www-data`) needs to read it.

### The Command

```bash
chown user:group file
```

### Examples

```bash
chown www-data:www-data /var/www/file.html    # Change owner and group
chown www-data /var/www/file.html              # Change owner only
chown -R www-data:www-data /var/www/           # Recursive (all files inside)
```

### Try It

```bash
# Create a file
touch testfile.txt
ls -la testfile.txt
# prathamesh:prathamesh

# Change owner (needs sudo)
sudo chown root:root testfile.txt
ls -la testfile.txt
# root:root

# Change back
sudo chown prathamesh:prathamesh testfile.txt

# Clean up
rm testfile.txt
```

### Exercise 3

1. Create a file, check its owner
2. `sudo chown root:root file` — change to root
3. `ls -la` — verify
4. Change back to your user

## Part 5: Special Bits — Sticky Bit, setuid, setgid (15 min)

### Sticky Bit (on directories)

```bash
chmod +t /tmp
ls -ld /tmp
# drwxrwxrwt
```

The `t` means: users can create files, but can only delete their own. That's why `/tmp` is safe for everyone.

### setuid (on executables)

```bash
ls -la /usr/bin/passwd
# -rwsr-xr-x
```

The `s` in user position means: when anyone runs this, it runs as the file owner (root). That's how `passwd` can change passwords — it runs as root.

### setgid (on directories)

```bash
chmod g+s /var/www/shared/
```

New files created inside this directory inherit the group. Useful for shared project directories.

### Try It

```bash
ls -la /usr/bin/passwd
ls -la /usr/bin/sudo
ls -ld /tmp
```

### Exercise 4

1. Run `ls -la /usr/bin/passwd` — find the `s` (setuid)
2. Run `ls -ld /tmp` — find the `t` (sticky bit)
3. Explain: Why does `passwd` need setuid?

## Part 6: Build Task — setup-permissions.sh (20 min)

### Create the File

```bash
cd devops-journey/sysadmin-toolkit
nano setup-permissions.sh
```

### Write This Script

```bash
#!/bin/bash

# setup-permissions.sh — Set correct permissions for a web server
# Usage: sudo ./setup-permissions.sh /var/www

WEB_DIR=${1:-"/var/www"}

if [ ! -d "$WEB_DIR" ]; then
    echo "Error: Directory $WEB_DIR does not exist"
    exit 1
fi

echo "Setting permissions for $WEB_DIR..."

# Directories: 755 (owner can write, others can enter)
find "$WEB_DIR" -type d -exec chmod 755 {} \;
echo "Directories set to 755"

# Files: 644 (owner can write, others can read)
find "$WEB_DIR" -type f -exec chmod 644 {} \;
echo "Files set to 644"

# Scripts: 755 (executable)
find "$WEB_DIR" -type f -name "*.sh" -exec chmod 755 {} \;
find "$WEB_DIR" -type f -name "*.py" -exec chmod 755 {} \;
echo "Scripts set to 755"

# Private keys: 600 (only owner can read)
find "$WEB_DIR" -type f -name "*.pem" -exec chmod 600 {} \;
find "$WEB_DIR" -type f -name "*.key" -exec chmod 600 {} \;
echo "Private keys set to 600"

# Config files: 640 (owner can write, group can read)
find "$WEB_DIR" -type f -name "*.conf" -exec chmod 640 {} \;
echo "Config files set to 640"

echo ""
echo "Done! Permissions set for $WEB_DIR"
echo ""
echo "Summary:"
echo "  Directories: 755 (rwxr-xr-x)"
echo "  Files:       644 (rw-r--r--)"
echo "  Scripts:     755 (rwxr-xr-x)"
echo "  Keys:        600 (rw-------)"
echo "  Configs:     640 (rw-r-----)"
```

### Make It Executable

```bash
chmod +x setup-permissions.sh
```

### Test It

```bash
# Create a test directory
mkdir -p ~/test-webdir
touch ~/test-webdir/index.html
touch ~/test-webdir/config.conf
touch ~/test-webdir/secret.key

# Run the script
./setup-permissions.sh ~/test-webdir

# Check results
ls -la ~/test-webdir/

# Clean up
rm -rf ~/test-webdir
```

### What You Just Built

A real sysadmin tool. When you set up a web server, run this script to ensure correct permissions.

## Part 7: Recap (5 min)

### What You Learned

| Command | Use Case |
|---------|----------|
| `ls -l` | Read permissions |
| `chmod` | Change permissions |
| `chown` | Change owner |
| `chmod +t` | Sticky bit |
| `chmod u+s` | setuid |

### The Pattern

When you get "Permission denied":
1. `ls -la file` — check current permissions
2. `chmod +x file` — add execute if needed
3. `chmod 644 file` — set correct permissions
4. `chown user:group file` — change owner if needed
