## Part 1: Why This Matters for Dorm-and-Dish (15 min)

Your Dorm-and-Dish backend runs on EC2. That EC2 lives inside a VPC. If the VPC is misconfigured — wrong subnet, missing route table, no IGW — your app is dead. No crash. No error. Just silence.

AWS networking is the #1 thing that trips up new cloud engineers. You can't `ping` a route table. You can't `ls` a security group. You reason about packets through layers you never see.

**This is what Cloud Support does daily.** "My app is unreachable" → trace VPC → subnet → route table → gateway → internet → find the broken link.

| Concept | What it does | Dorm-and-Dish use |
|---------|-------------|-------------------|
| VPC | Your private cloud network | Isolate Dorm-and-Dish from other accounts |
| Subnet | Chunk of VPC IP space | Public = web/bastion, private = backend/DB |
| Route Table | Rules for where traffic goes | `0.0.0.0/0` → IGW (public) or NAT GW (private) |
| Internet Gateway (IGW) | VPC ↔ internet door, both directions | Public subnet needs this |
| NAT Gateway | Private → internet valve, outbound-only | Backend `apt update` without public IP |
| CIDR Block | IP range | `10.21.0.0/16` = 65,536 IPs for this lab |

### Feeder Role Relevance

**Today's skill is relevant to:** Cloud Support Engineer, NOC Technician, Junior System Administrator, Infrastructure Support.

**Why:** "My EC2 can't reach the internet" is a top support ticket. Fix is almost always route table / subnet / gateway.

## Part 7: Troubleshooting Challenge (30 min)

**Rule: cover steps 1-4 yourself first, then uncover 5-9.**

### Scenario

You're Cloud Support. Ticket: "EC2 in private subnet can't install packages, 2 hours stuck. SG allows all outbound. About to recreate everything." Known: VPC `10.21.0.0/16`, private `10.21.2.0/24`, no public IP, NAT exists in public subnet, `apt update` hangs, `curl` times out, internal pings fine.

### Investigation Path

1. **SYMPTOM:** `apt` hangs, `curl` times out, internal pings work.
2. **OBSERVATION:** Internal works, external doesn't → outbound path only.
3. **HYPOTHESIS:** Route table vs NAT GW vs IGW vs NACL. Bet route table (most common).
4. **CHECK:** VPC → Route Tables → select the table associated with `day21-lab-private` → Routes tab. Is there a `0.0.0.0/0` row? Then VPC → NAT Gateways → is `day21-lab-nat` State = Available in `day21-lab-public`?
5. **EVIDENCE:** Only `10.21.0.0/16 → local`. No `0.0.0.0/0`.
6. **ROOT CAUSE:** Missing default route — internet traffic has nowhere to go.
7. **FIX (console):** VPC → Route Tables → `day21-private-rt` → Routes → Edit → Add route: Destination `0.0.0.0/0`, Target → NAT Gateway → `day21-lab-nat` → Save.
8. **VERIFY (on backend):** `curl -I http://example.com` → 200; `sudo apt update` → hits repos.
9. **PREVENTION:** Define route tables in code (Terraform Day 24+) with explicit `0.0.0.0/0`. Never rely on console defaults — private subnets get NO default route automatically.

### Why This Happens

Console auto-adds `0.0.0.0/0 → IGW` for public. Private gets nothing automatically. Manual miss = this exact ticket.

## Part 8: Build Task — Network Diagnostic Checklist (60 min)

Support-ticket checklist version of the script below. Work it in the console + SSH; the script is the same logic automated for later.

### Create the File (VS Code / Notepad — bash script, run in Git Bash)

Create `scripts/vpc-diagnose.sh` in your lab notes repo and paste the script below.

### Write This Script

```bash
#!/bin/bash
# vpc-diagnose.sh — Quick VPC networking health check
# Usage: ./vpc-diagnose.sh <instance-id> <region>

set -euo pipefail

INSTANCE_ID="${1:?Usage: $0 <instance-id> <region>}"
REGION="${2:?Usage: $0 <instance-id> <region>}"

echo "=== VPC Network Diagnostic for $INSTANCE_ID ==="
echo "Region: $REGION"
echo ""

echo "[1/6] Fetching instance details..."
INSTANCE_INFO=$(aws ec2 describe-instances \
  --instance-ids "$INSTANCE_ID" \
  --region "$REGION" \
  --query 'Reservations[0].Instances[0].[State.Name,PublicIpAddress,PrivateIpAddress,SubnetId,VpcId]' \
  --output text)

STATE=$(echo "$INSTANCE_INFO" | awk '{print $1}')
PUBLIC_IP=$(echo "$INSTANCE_INFO" | awk '{print $2}')
PRIVATE_IP=$(echo "$INSTANCE_INFO" | awk '{print $3}')
SUBNET_ID=$(echo "$INSTANCE_INFO" | awk '{print $4}')
VPC_ID=$(echo "$INSTANCE_INFO" | awk '{print $5}')

echo "  State: $STATE"
echo "  Public IP: ${PUBLIC_IP:-none}"
echo "  Private IP: $PRIVATE_IP"
echo "  Subnet: $SUBNET_ID"
echo "  VPC: $VPC_ID"
echo ""

echo "[2/6] Checking subnet configuration..."
MAP_PUBLIC=$(aws ec2 describe-subnets \
  --subnet-ids "$SUBNET_ID" \
  --region "$REGION" \
  --query 'Subnets[0].MapPublicIpOnLaunch' \
  --output text)

echo "  MapPublicIpOnLaunch: $MAP_PUBLIC"
if [ "$MAP_PUBLIC" = "True" ]; then
  echo "  -> Subnet is PUBLIC"
else
  echo "  -> Subnet is PRIVATE"
fi
echo ""

echo "[3/6] Checking route table..."
RT_ID=$(aws ec2 describe-route-tables \
  --region "$REGION" \
  --filters "Name=association.subnet-id,Values=$SUBNET_ID" \
  --query 'RouteTables[0].RouteTableId' \
  --output text)

echo "  Route Table: $RT_ID"

ROUTES=$(aws ec2 describe-route-tables \
  --route-table-ids "$RT_ID" \
  --region "$REGION" \
  --query 'RouteTables[0].Routes[*].[DestinationCidrBlock,GatewayId,NatGatewayId]' \
  --output text)

echo "  Routes:"
echo "$ROUTES" | while read -r DEST GW NAT; do
  echo "    $DEST -> gw:${GW:-none} nat:${NAT:-none}"
done

DEFAULT_ROUTE=$(echo "$ROUTES" | grep "0.0.0.0/0" || true)
if [ -z "$DEFAULT_ROUTE" ]; then
  echo "  WARNING: No default route (0.0.0.0/0) found!"
  echo "  -> Instance cannot reach the internet"
else
  echo "  OK: Default route exists"
fi
echo ""

echo "[4/6] Checking gateways..."
IGW=$(aws ec2 describe-internet-gateways \
  --region "$REGION" \
  --filters "Name=attachment.vpc-id,Values=$VPC_ID" \
  --query 'InternetGateways[0].InternetGatewayId' \
  --output text 2>/dev/null || echo "none")

echo "  Internet Gateway: $IGW"

NAT_GW=$(aws ec2 describe-nat-gateways \
  --region "$REGION" \
  --filter "Name=vpc-id,Values=$VPC_ID" \
  --query 'NatGateways[?State==`available`].NatGatewayId | [0]' \
  --output text 2>/dev/null || echo "none")

echo "  NAT Gateway (available in VPC): $NAT_GW"
echo ""

echo "[5/6] Checking security groups..."
SG_IDS=$(aws ec2 describe-instances \
  --instance-ids "$INSTANCE_ID" \
  --region "$REGION" \
  --query 'Reservations[0].Instances[0].SecurityGroups[*].GroupId' \
  --output text)

echo "  Security Groups: $SG_IDS"

for SG in $SG_IDS; do
  OUTBOUND=$(aws ec2 describe-security-groups \
    --group-ids "$SG" \
    --region "$REGION" \
    --query "SecurityGroups[0].IpPermissionsEgress[?IpProtocol=='-1']" \
    --output text 2>/dev/null || echo "restricted")

  if [ -n "$OUTBOUND" ] && [ "$OUTBOUND" != "restricted" ]; then
    echo "  OK: $SG allows all outbound"
  else
    echo "  CHECK: $SG has restricted outbound rules"
  fi
done
echo ""

echo "[6/6] Quick connectivity summary..."
if [ "$MAP_PUBLIC" = "True" ] && [ "$PUBLIC_IP" != "None" ] && [ -n "$PUBLIC_IP" ]; then
  echo "  Public subnet + public IP -> should have internet access"
elif [ "$MAP_PUBLIC" = "False" ]; then
  if echo "$DEFAULT_ROUTE" | grep -q "nat"; then
    echo "  Private subnet + NAT route -> should have outbound internet"
  else
    echo "  FAIL: Private subnet + NO NAT route -> NO internet access"
    echo "  FIX: Add 0.0.0.0/0 -> NAT Gateway to the route table"
  fi
fi

echo ""
echo "=== Diagnostic Complete ==="
```

## Part 9: Root-Cause Discussion (15 min)

Removing `0.0.0.0/0 → NAT` cut the only internet path. `10.21.0.0/16 → local` kept VPC-internal alive — hence pings work, everything external hangs.

| Symptom | Meaning |
|---------|---------|
| Internal pings work | VPC routing fine |
| `curl` times out | No route to external IPs |
| `nslookup` fails | DNS leaves VPC, blocked |
| `apt update` hangs | HTTP to repos blocked |

**Pattern:** internal works + external doesn't = route table or gateway. Not DNS. Not SG. Not NACL (usually).

Mental model — trace the packet:
```
Instance → Subnet → Route Table → [Gateway] → Internet
              ↑            ↑              ↑
         Is it here?  Correct route?  Attached + Available?
```
First broken link = root cause.
