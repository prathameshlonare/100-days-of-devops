## Part 1: Greenfield vs Brownfield & The Core Mental Model (15 min)

In Days 24 through 29, you practiced **Greenfield Infrastructure**:
- You wrote `.tf` code first, ran `terraform apply`, and Terraform created brand-new resources in AWS from zero.

In real-world companies and your academic projects (like Dorm-and-Dish and the Online Voting System), you face **Brownfield Infrastructure**:
- Infrastructure was already built manually in the AWS Console months ago.
- If you simply write `resource "aws_s3_bucket" "dorm_dish_assets" { bucket = "existing-name" }` and run `terraform apply`, Terraform **crashes** with:
  `BucketAlreadyExists: The requested bucket name is not available.`
- Why? Because `terraform.tfstate` is empty! Terraform does not know that *you* own that bucket; it thinks it needs to create a brand new one.

```
[ THE IMPORT MECHANISM ]

Step 1: Resource physically exists in AWS (Console Click-Ops)
        AWS S3: "day30-console-asset-bucket-12345"
                           ▲
                           │  (terraform import bridges the gap)
                           ▼
Step 2: Terraform State records live resource attributes
        terraform.tfstate  <-- Populated with ARN, bucket ID, region, etc.
                           ▲
                           │  (terraform plan computes zero delta)
                           ▼
Step 3: Source Code mirrors state
        main.tf: resource "aws_s3_bucket" "dorm_dish_assets"
```

The `terraform import` command (and Terraform 1.5+ `import {}` blocks) reads the existing cloud resource and writes its mapping into `terraform.tfstate` **without touching or destroying the live resource**.

## Part 3: Break-It Lab — Import ID Mismatch & Blind Import Crash (45 min)

**INTENTIONAL BREAK-FIX DRILL — Safe scratch lab.**

### The Problem: Importing with the Wrong Identifier
Every Terraform resource type expects a specific identifier format during import:
- `aws_s3_bucket` expects the **Bucket Name** (e.g. `my-bucket`).
- `aws_instance` expects the **Instance ID** (e.g. `i-0123456789abcdef0`).
- `aws_route_table_association` expects `subnet_id/route_table_id`.
- `aws_security_group_rule` expects `sg_id_type_protocol_fromport_toport_cidr`.

What happens when an engineer tries to import a resource using an invalid ID or ARN?

---

### Step 1: Trigger the Failure
Attempt to import using an ARN instead of the bucket name:

```powershell
terraform import aws_s3_bucket.dorm_dish_assets arn:aws:s3:::day30-console-asset-bucket-<your-account-id>
```

### Symptoms to Observe
```text
╷
│ Error: parsing "arn:aws:s3:::day30-console-asset-bucket-...": invalid S3 bucket name
│ 
│ Cannot import non-existent or invalid remote object
╵
```
Terraform halts. The state file remains protected and unchanged.

---

### Step 2: The Modern Terraform 1.5+ Declarative Import
Instead of running imperative CLI commands (`terraform import ...`), modern enterprise Terraform uses **declarative `import {}` blocks** directly in HCL code.

Add this block to your `main.tf`:

```hcl
import {
  to = aws_s3_bucket.dorm_dish_assets
  id = "day30-console-asset-bucket-<your-account-id>"
}
```

Now, anyone on your team running `terraform plan` will automatically see the import plan without needing manual CLI commands!

## Part 5: CHECKPOINT 2 — Cloud Support Gate Review (30 min)

You have completed Phase 5. Review these 10 core competencies aloud. These are the exact technical questions asked in Amazon, Cloud Consultancy, and Tier-1 DevOps interviews:

| Topic | Core Technical Mechanism | The "Why" Behind It |
|---|---|---|
| **1. EC2 Status Checks** | System Status (hardware/hypervisor) vs Instance Status (OS kernel/networking) | Determines whether AWS host migration (`stop/start`) or OS triage (`journalctl`/recovery volume) is needed. |
| **2. SSH Triage** | Port 22 SG rule -> Network ACL ephemeral return ports -> OS `sshd.service` -> Key pair permissions | Isolates connection drops methodically from network boundary to on-box daemon. |
| **3. VPC Routing** | Route Table `0.0.0.0/0 -> igw` (Public) vs `0.0.0.0/0 -> nat-gateway` (Private) | Prevents exposing private database subnets directly to the internet while allowing outbound patching. |
| **4. SG vs NACL** | Security Group is **stateful**; NACL is **stateless** (requires ephemeral ports 1024-65535) | Security Groups track connection tables automatically; NACLs drop return packets if ephemeral rules are missing. |
| **5. Terraform HCL** | Declarative configuration compiled into a Directed Acyclic Graph (DAG) | You specify the desired end-state; Terraform computes the dependency execution graph. |
| **6. Dynamic AMI Lookups** | `data "aws_ssm_parameter"` for Ubuntu or `data "aws_ami"` filters for AL2023 | Eliminates hardcoded regional AMI IDs that break across regions and rot on OS patch Tuesdays. |
| **7. Remote State Locking** | S3 (encrypted versioned storage) + DynamoDB (`attribute_not_exists(LockID)` mutex) | Prevents two engineers or CI pipelines from running `apply` concurrently and corrupting state. |
| **8. Reusable Modules** | Child modules communicate strictly via `variables.tf` (in) and `outputs.tf` (out) | Shrinks blast radius from 500-line monolithic files down to isolated, testable building blocks. |
| **9. Workspaces & Drift** | Workspaces partition state (`terraform.tfstate.d/`); `plan` refreshes live AWS reality | Code is the single source of truth; unauthorized manual Console edits are spotted and stripped. |
| **10. Teardown Triage** | Inverted DAG graph; `DependencyViolation` when unmanaged ENIs exist in a subnet | Teardowns delete from inside out; invisible out-of-band ENIs block subnet/VPC destruction. |
