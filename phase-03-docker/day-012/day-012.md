## Part 1: Why This Matters for Online-voting-system (10 min)

Your React voting app runs fine on your machine. But when you shared it with a friend, three things broke:

1. **Node version mismatch** — You have Node 18, they have Node 16
2. **OS differences** — You're on Linux, they're on Windows
3. **Missing dependencies** — `npm install` behaved differently

Docker fixes all three. One Dockerfile = same environment everywhere.

| Concept | What it does | When I'd use it |
|---------|--------------|-----------------|
| Dockerfile | Recipe to build an environment | Containerize my React app |
| Image | Frozen snapshot of that environment | Share a working build with anyone |
| Container | Running instance of an image | Run my app locally or on a server |
| `docker build` | Turns Dockerfile into an image | Build my app's environment |
| `docker run` | Starts a container from an image | Run my app in that environment |
| `docker ps` | Shows running containers | Check if my app is running |

## Part 2: What Are Containers? (15 min)

### The Problem

Before Docker, you'd say "it works on my machine." After Docker, you say "it works in this container." The container IS the machine — portable, repeatable, isolated.

### The Concept

Think of a container like a lightweight virtual machine:

| VM | Container |
|----|-----------|
| Full OS (GBs) | Shared kernel (MBs) |
| Minutes to start | Seconds to start |
| Heavy isolation | Process-level isolation |
| Fixed resources | Flexible resources |

Docker containers share your Linux kernel but isolate everything else — files, network, processes. That's why they're fast AND isolated.

```

You should see something like:

```

If not installed, download Docker Desktop from docker.com and install it.

## Part 3: Writing Your First Dockerfile (20 min)

### The Problem

Online-voting-system's React frontend needs Node 18, npm dependencies, and specific build steps. Instead of documenting "install Node 18, then run npm install, then npm run build," we write a Dockerfile that does it all automatically.

### The Command

Create a Dockerfile in your project root:

```bash
cd ~/Online-voting-system
nano Dockerfile
```

Write this:

```dockerfile
# Stage 1: Build the React app
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Serve the built app
FROM node:18-alpine
WORKDIR /app
RUN npm install -g serve
COPY --from=builder /app/build ./build
EXPOSE 3000
CMD ["serve", "-s", "build", "-l", "3000"]
```

Let's break it down:

- `FROM node:18-alpine` — Start with Node 18 (Alpine = small Linux)
- `WORKDIR /app` — Set working directory inside container
- `COPY package*.json ./` — Copy dependency list first (cache layer)
- `RUN npm ci` — Install dependencies (clean install, no lockfile changes)
- `COPY . .` — Copy all source code
- `RUN npm run build` — Build the React app
- `EXPOSE 3000` — Document that this container uses port 3000
- `CMD ["serve", ...]` — What to run when container starts

### Why Two Stages?

The multi-stage build keeps your final image small:
- **Stage 1 (builder):** Has Node, npm, all dev dependencies. Builds the React app.
- **Stage 2 (final):** Only has the built `build/` folder and a static file server. No source code, no dev dependencies.

Result: ~150MB instead of ~800MB.

### Exercise 2

1. Create the Dockerfile in your Online-voting-system root
2. Read through each line — can you explain what each instruction does?
3. Create a `.dockerignore` file:

```
node_modules
build
.git
.env
```

This tells Docker to skip these files when copying.

## Part 4: Building and Running the Container (20 min)

### The Problem

You have a Dockerfile. Now you need to turn it into a running container.

### The Commands

**Build the image:**

```bash
docker build -t voting-app .
```

- `-t voting-app` — Tag (name) the image "voting-app"
- `.` — Build from the current directory (where Dockerfile is)

You'll see:

```
[+] Building 45.2s (10/10) FINISHED
 => [builder 1/5] FROM docker.io/library/node:18-alpine
 => [builder 2/5] WORKDIR /app
 ...
 => => exporting to image
 => => naming to docker.io/library/voting-app
```

**Run the container:**

```bash
docker run -p 3000:3000 voting-app
```

- `-p 3000:3000` — Map port 3000 on your machine to port 3000 in the container

Open `http://localhost:3000` — your voting app is running inside a container.

**Run in background (detached):**

```bash
docker run -d -p 3000:3000 --name voting-container voting-app
```

- `-d` — Run in background (detached mode)
- `--name voting-container` — Give the container a name

**Check it's running:**

```bash
docker ps
```

You'll see:

```
CONTAINER ID   IMAGE        COMMAND                  STATUS         PORTS                    NAMES
a1b2c3d4e5f6   voting-app   "serve -s build -l 3000" Up 2 minutes  0.0.0.0:3000->3000/tcp   voting-container
```

### What This Tells You

| Column | Meaning |
|--------|---------|
| CONTAINER ID | Unique identifier (use first few chars) |
| IMAGE | Which image this container runs |
| COMMAND | What's running inside |
| STATUS | How long it's been running |
| PORTS | Port mapping (host:container) |
| NAMES | Human-readable name |

### Exercise 3

1. Build the image: `docker build -t voting-app .`
2. Run it: `docker run -d -p 3000:3000 --name voting-container voting-app`
3. Check `docker ps` — is it running?
4. Open `http://localhost:3000` — does the app work?
5. Check logs: `docker logs voting-container`
6. Stop it: `docker stop voting-container`
7. Remove it: `docker rm voting-container`

## Part 5: Build Task — containerize-and-run.sh (25 min)

Now combine everything into a reusable script.

### Create the File

```bash
cd ~/Online-voting-system
nano containerize-and-run.sh
```

### Write This Script

```bash
#!/bin/bash

# containerize-and-run.sh
# Builds and runs the Online-voting-system React frontend in Docker
# Usage: ./containerize-and-run.sh [port]

set -e

PORT=${1:-3000}
IMAGE_NAME="voting-app"
CONTAINER_NAME="voting-container"

echo "=== Docker Container Setup for Online-voting-system ==="
echo ""

# Check if Docker is running
if ! docker info > /dev/null 2>&1; then
    echo "ERROR: Docker is not running. Start Docker Desktop and try again."
    exit 1
fi

# Stop and remove existing container if running
if docker ps -a --format '{{.Names}}' | grep -q "^${CONTAINER_NAME}$"; then
    echo "Stopping existing container..."
    docker stop "$CONTAINER_NAME" > /dev/null 2>&1 || true
    docker rm "$CONTAINER_NAME" > /dev/null 2>&1 || true
fi

# Build the image
echo "Building Docker image..."
docker build -t "$IMAGE_NAME" .

# Run the container
echo "Starting container on port $PORT..."
docker run -d \
    -p "$PORT:3000" \
    --name "$CONTAINER_NAME" \
    "$IMAGE_NAME"

echo ""
echo "=== Container is running ==="
echo "URL: http://localhost:$PORT"
echo "Container name: $CONTAINER_NAME"
echo ""
echo "Useful commands:"
echo "  docker logs $CONTAINER_NAME    — View logs"
echo "  docker stop $CONTAINER_NAME    — Stop container"
echo "  docker rm $CONTAINER_NAME      — Remove container"
echo "  docker ps                      — List running containers"
```

### Make It Executable

```bash
chmod +x containerize-and-run.sh
```

### Test It

```bash
./containerize-and-run.sh
```

You'll see:

```
=== Docker Container Setup for Online-voting-system ===

Building Docker image...
[+] Building 45.2s (10/10) FINISHED
Starting container on port 3000...

=== Container is running ===
URL: http://localhost:3000
Container name: voting-container

Useful commands:
  docker logs voting-container    — View logs
  docker stop voting-container    — Stop container
  docker rm voting-container      — Remove container
  docker ps                      — List running containers
```

### Test with Different Port

```bash
./containerize-and-run.sh 8080
```

Now it runs on `http://localhost:8080`.

### What You Just Built

A one-command setup for your React app. Anyone with Docker can run your voting app without installing Node, npm, or any dependencies. That's the power of containers — "it works on my machine" becomes "it works in this container."

## Part 6: Recap (5 min)

### What You Learned

| Concept | Use Case | My Project |
|---------|----------|------------|
| Dockerfile | Define build environment | Build React frontend |
| `docker build` | Create image from Dockerfile | Build voting-app image |
| `docker run` | Start container from image | Run app in container |
| `-p` flag | Map ports | Access app on localhost |
| `-d` flag | Run in background | Keep app running |
| Multi-stage build | Smaller images | 150MB instead of 800MB |
| `.dockerignore` | Skip files | Exclude node_modules |

### The Pattern

When your app works locally but breaks on someone else's machine:
1. **Write a Dockerfile** — Define the exact environment (Node version, dependencies, build steps)
2. **Build the image** — `docker build -t name .`
3. **Run the container** — `docker run -d -p 3000:3000 name`
4. **Share the Dockerfile** — Anyone can reproduce your environment
