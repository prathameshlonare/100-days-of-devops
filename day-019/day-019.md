## Part 2: Docker Build in GitHub Actions (20 min)

### The Problem

Your pipeline lints and tests, but doesn't build a Docker image. You still run `docker build` locally and push manually. Let's automate it.

### The Command

```bash
cd ~/Online-voting-system
cat .github/workflows/ci.yml
```

### Add Docker Build Job

```yaml
  build:
    name: Build Docker Image
    needs: [lint, test]              # Only if lint + test pass
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: ap-south-1

      - name: Login to ECR
        id: login-ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: Build Docker image
        env:
          ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
          ECR_REPOSITORY: voting-frontend
          IMAGE_TAG: ${{ github.sha }}
        run: |
          docker build -t $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG .
          docker tag $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG $ECR_REGISTRY/$ECR_REPOSITORY:latest

      - name: Push to ECR
        env:
          ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
          ECR_REPOSITORY: voting-frontend
          IMAGE_TAG: ${{ github.sha }}
        run: |
          docker push $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG
          docker push $ECR_REGISTRY/$ECR_REPOSITORY:latest
```

### Line-by-Line Breakdown

| Line | What it does | Why it matters |
|------|--------------|----------------|
| `needs: [lint, test]` | Waits for lint + test | Don't build broken code |
| `aws-actions/configure-aws-credentials@v4` | Loads AWS keys from secrets | Secure — no hardcoded keys |
| `aws-actions/amazon-ecr-login@v2` | Gets ECR login token | Docker needs auth to push |
| `docker build -t ...` | Builds image with tag | `$github.sha` = commit hash |
| `docker push ...` | Pushes to ECR | Image available for ECS |

### Try It Now

```bash

# Check if you have AWS credentials configured

# If not, configure them

```

## Part 3: Trivy Security Scan (20 min)

### The Problem

Your image builds and pushes. But is it secure? Trivy scans your Docker image for known vulnerabilities (CVEs) before you deploy.

### The Command

```bash
# Install Trivy locally (for testing)
brew install trivy          # macOS
sudo apt-get install trivy  # Ubuntu

# Scan an image
trivy image voting-frontend:latest
```

### Add Trivy Scan to Pipeline

```yaml
  security-scan:
    name: Security Scan
    needs: [build]
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Run Trivy vulnerability scanner
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ${{ secrets.AWS_REGISTRY }}/${{ github.event.repository.name }}:${{ github.sha }}
          format: 'table'
          exit-code: '1'              # Fail if HIGH or CRITICAL found
          severity: 'CRITICAL,HIGH'
          ignore-unfixed: true
```

### Trivy Output

```

=====================================
Total: 152 (UNKNOWN: 0, LOW: 85, MEDIUM: 47, HIGH: 18, CRITICAL: 2)

┌────────────────┬──────────────┬──────────┬─────────────────┬───────────────┬──────────────────────────────────────────────────┐
│    Library     │ Vulnerability │ Severity │  Fixed Version  │     URI      │                     Description                  │
├────────────────┼──────────────┼──────────┼─────────────────┼───────────────┼──────────────────────────────────────────────────┤
│ libssl1.1      │ CVE-2024-XXX │ HIGH     │  1.1.1w-0+deb11 │ glsa:XXX     │ OpenSSL: certificate verification bypass         │
└────────────────┴──────────────┴──────────┴─────────────────┴───────────────┴──────────────────────────────────────────────────┘
```

### What Each Flag Does

| Flag | What it does | Why it matters |
|------|--------------|----------------|
| `image-ref` | Which image to scan | Your just-built image |
| `format: 'table'` | Human-readable output | Easy to read in logs |
| `exit-code: '1'` | Fail pipeline if vulns found | Blocks bad images |
| `severity: 'CRITICAL,HIGH'` | Only fail on serious issues | Ignores LOW/MEDIUM |
| `ignore-unfixed: true` | Skip vulns without patches | Can't fix what has no fix |

### Try It Now

```bash

# Scan with only CRITICAL severity
trivy image --severity CRITICAL voting-frontend:latest

# Scan and output as JSON
trivy image --format json voting-frontend:latest
```

## Part 4: Full Pipeline — All Together (15 min)

### The Problem

You have lint, test, build, and security scan as separate pieces. Let's combine them into one workflow.

### Complete Pipeline

```yaml
name: CI/CD Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

env:
  NODE_VERSION: '18'
  AWS_REGION: ap-south-1
  ECR_REPOSITORY: voting-frontend

jobs:
  lint:
    name: Lint
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'
      - run: npm ci
      - run: npm run lint

  test:
    name: Test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'
      - run: npm ci
      - run: npm test

  build:
    name: Build & Push
    needs: [lint, test]
    runs-on: ubuntu-latest
    outputs:
      image-tag: ${{ steps.meta.outputs.version }}
    steps:
      - uses: actions/checkout@v4

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: ${{ env.AWS_REGION }}

      - name: Login to ECR
        id: login-ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: Docker meta
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}
          tags: |
            type=sha,prefix=
            type=raw,value=latest

      - name: Build and push
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  security-scan:
    name: Security Scan
    needs: [build]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Run Trivy
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ${{ secrets.AWS_REGISTRY }}/${{ env.ECR_REPOSITORY }}:${{ github.sha }}
          format: 'table'
          exit-code: '1'
          severity: 'CRITICAL,HIGH'
          ignore-unfixed: true
```

### Pipeline Flow

```
┌───────────┐     ┌───────────┐
│   LINT    │     │   TEST    │     ← Parallel
└─────┬─────┘     └─────┬─────┘
      │                 │
      └────────┬────────┘
               │
               ▼
        ┌─────────────┐
        │ BUILD & PUSH│     ← ECR
        └──────┬──────┘
               │
               ▼
        ┌─────────────┐
        │  TRIVY SCAN │     ← Security gate
        └─────────────┘
```

## Part 5: Build Task — docker-build.yml (30 min)

Create a separate workflow for Docker builds (keeps CI and CD organized).

### Create the File

```bash
cd ~/Online-voting-system
nano .github/workflows/docker-build.yml
```

### Write This Workflow

```yaml
name: Docker Build & Push

on:
  push:
    branches: [main]
    paths:
      - 'docker/**'
      - 'frontend/**'
      - '.github/workflows/docker-build.yml'

env:
  AWS_REGION: ap-south-1
  ECR_REPOSITORY: voting-frontend

jobs:
  build-and-push:
    name: Build & Push to ECR
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: ${{ env.AWS_REGION }}

      - name: Login to Amazon ECR
        id: login-ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: Docker metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}
          tags: |
            type=sha,prefix=
            type=raw,value=latest

      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          file: docker/Dockerfile.frontend.prod
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  security-scan:
    name: Trivy Security Scan
    needs: [build-and-push]
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Run Trivy vulnerability scanner
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}:${{ github.sha }}
          format: 'table'
          exit-code: '1'
          severity: 'CRITICAL,HIGH'
          ignore-unfixed: true
          exit-code: '1'

      - name: Trivy output
        if: always()
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}:${{ github.sha }}
          format: 'json'
          output: 'trivy-results.json'

      - name: Upload Trivy results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: trivy-results
          path: trivy-results.json
```

### Make It Executable

```bash
git add .github/workflows/docker-build.yml
git commit -m "ci: add Docker build + ECR push + Trivy scan"
git push origin main
```

### Test It

1. Make a change to any file in `docker/` or `frontend/`
2. Push to main
3. Watch the pipeline:
   - Build Docker image
   - Push to ECR (with commit hash tag)
   - Run Trivy security scan
   - Upload scan results as artifact

### What You Just Built

A production-grade CI/CD pipeline that:
- Triggers on code changes (not every push)
- Builds optimized Docker image (multi-stage)
- Pushes to AWS ECR with version tags
- Scans for vulnerabilities before deploy
- Fails pipeline if CRITICAL/HIGH CVEs found

## Part 6: Recap (5 min)

### What You Learned

| Concept | Use Case | Online-voting-system |
|---------|----------|---------------------|
| Docker build in CI | Auto-build on push | `.github/workflows/docker-build.yml` |
| ECR push | Store images in AWS | `voting-frontend:sha` |
| Trivy scan | Security gate | Block CRITICAL/HIGH CVEs |
| `paths:` trigger | Only run on relevant changes | `docker/**`, `frontend/**` |
| `docker/build-push-action` | Optimized build + push | Cache layers with GHA cache |

### The Pattern

When adding Docker to CI/CD:
1. **Configure AWS credentials** — use GitHub secrets, never hardcode
2. **Login to ECR** — get auth token
3. **Build + push** — use docker/build-push-action for caching
4. **Scan with Trivy** — security gate before deploy
5. **Fail on CRITICAL** — don't deploy vulnerable images
