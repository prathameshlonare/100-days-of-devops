## Part 2: Branch Naming Convention (15 min)

### The Problem

On Online-voting-system, you probably have branches named `test`, `fix`, `new-stuff`, `temp`. Nobody — including you — knows what they do.

### The Convention

```
feature/[description]    → new features
fix/[description]        → bug fixes
hotfix/[description]     → urgent production fixes
docs/[description]       → documentation only
```

## Part 3: Merge Strategy (20 min)

### The Problem

You merge a PR. Now what? Do you rebase? Do you merge commit? Do you squash? If you don't decide now, you'll decide differently every time.

### The Strategy

For personal projects at this level, keep it simple:

```
Squash merge for small changes (1-3 commits)
Regular merge for big features (5+ commits)
Never rebase shared branches
```

### Try It Now

```bash
cd ~/Online-voting-system
git log --oneline -10
```

Look at your commit history. Would squash merge have made this cleaner?

## Part 4: Cleanup Flow (15 min)

### The Problem

You merge a PR but forget to delete the branch. Now you have50 stale branches nobody remembers.

### The Flow

```
Merge PR → Delete remote branch → Pull locally → Done
```

GitHub auto-deletes remote branches after merge if you enable it. But don't rely on that — build the habit.

### Try It Now

```bash
# After merging a PR
git branch -d feature/old-branch        # delete local
git push origin --delete feature/old-branch  # delete remote
git pull origin main                    # sync local
```

Now combine everything into a real document.

### Create the File

```bash
cd ~/Online-voting-system

```

### Write This Document

```markdown
# Branching Strategy

## Rules

1. `main` is always deployable
2. Every change goes through a branch + PR
3. Branch naming: `feature/`, `fix/`, `hotfix/`, `docs/`
4. Never push directly to `main`
5. PR must have: title, description, at least 1 review (self-review OK for solo)
6. After merge: delete branch, pull locally

## Workflow

```
git checkout main
git pull origin main
git checkout -b feature/your-feature
# make changes
git add .
git commit -m "feat: description"
git push origin feature/your-feature
# open PR on GitHub
# merge → delete → pull locally

### The Pattern

When starting any Git work:
1. `git pull origin main` — always start from latest
2. `git checkout -b feature/name` — never work on main
3. Commit often, push regularly
4. Open PR, review yourself, merge
5. Delete branch, pull locally
